Phase 2: 4,000 Lines Deleted, 1,200 Tests Reorganized, 1 Race Condition Found

The honest story: we didn't scale to 2,000 tests. We cleaned up a mess that AI helped create.

In my first article, I showed how AI helped scale tests from 60 to 456 on a $0 budget. What I didn't show: the mess it left behind.

Money paragraph: Two files — nearly 4,000 lines. One was a 2,349-line UI monolith with 15 copy-pasted API blocks. The other was a 1,559-line API duplicate. That's not scale. That's technical debt. Phase 2: ~4,000 lines from 2 monoliths → 23 modules, 1,200 real tests (×4 browsers = 1,057 Playwright runs), 1 race condition fixed, 12 AI models tried — 5 still free.

1. The Mess Nobody Talks About

AI doesn't create tech debt on its own. It amplifies what you put in. Bad prompt → bad architecture. And that's my fault.

Phase 1: I started without a strong prompt. Just "write tests" — and AI generated ~4,000 lines of monoliths in weeks. Fast. But without architecture. One file contained 2,349 lines of UI tests with 15 copy-pasted API blocks. AI isn't to blame — I didn't tell it how.

3. The Bug We Found by Accident

While rewriting tests under the modular structure, something unexpected happened — we found a real bug that had been living in production for weeks.

🩻 Postmortem: Refresh token race condition. Root cause: datetime.now() as JWT exp → same microsecond → same JWT → unique_violation in PostgreSQL. Fix: jti: uuid.uuid4() — one line in the token payload.

We didn't find it through testing. We found it because the modular split forced us to actually read the code. The race had been there since day one (April). Automated tests passed every time because the probability of hitting the exact microsecond collision was low — until you run 4 parallel browser projects.

6. Honest Take

Free AI is a treadmill — keep moving or get left behind.

In 2 months, 7 out of 17 AI tools I tried either disappeared, changed pricing, or hit limits. The 5 that remain are from different providers: OpenCode (3 models), Groq (1), Ollama (1 local). No single source of truth.

The biggest surprise? The race condition. We didn't find it with smarter tests or better coverage. We found it because refactoring forced us to read the code. That's a humbling lesson for anyone who thinks "more tests = better quality." Sometimes the best test improvement is deleting 4,000 lines and starting cleaner.

TL;DR: AI is great at writing new code. Refactoring existing code — especially code that AI wrote — is still a human-led effort. The tools help. The human decides. And occasionally, cleaning up the mess finds a bug that testing never could.
